# Instalación y configuración de un SIEM (HFM)

## Caso de Uso y Objetivos
Duration: 0:05:00

El objetivo principal de este proyecto ha sido montar un entorno de laboratorio (o prueba de concepto) para poder simular, detectar y monitorizar ciberataques en tiempo real contra una infraestructura concreta.

Este escenario práctico sirve para:
* Levantar un servidor víctima con servicios expuestos (SSH, Nginx).
* Meter un Sistema de Detección de Intrusos (Snort) configurado con reglas personalizadas para cazar escaneos de red (ICMP) y ataques de fuerza bruta (SSH).
* Recoger, ordenar y enviar todas estas alertas a un panel centralizado.

Para montar todo esto, optamos por **ELK** (Elasticsearch, Logstash y Kibana). Principalmente porque trae los datos y los muestra en tiempo real y porque, además de ser una solución súper robusta que se usa a nivel corporativo, es gratuita y de código abierto.

## Proceso de Instalación: SIEM (ELK) y Servidor Víctima
Duration: 0:10:00

Para asegurarnos de que el entorno sea fácil de replicar, tiramos de **Docker Desktop** para meter cada componente en su propio contenedor.

### Preparación y contenedores

**1. Creación de la red virtual:**
```bash
docker network create elk-red
```
![Creación de red virtual](img/Captura%20de%20pantalla%202026-02-20%20131142.png)

**2. Lanzar el contenedor ELK con las redes y el límite de memoria:**

> **Advertencia:** Mover la pila ELK en el equipo de pruebas se comió más del 90% de los 32 GB de RAM disponibles. Así que, antes de tocar nada, toca cerrar todo lo que no sea estrictamente necesario. Tuvimos que ponernos serios con los límites de memoria (2GB para Elasticsearch y 2GB para Filebeat) para evitar el colapso (*Out of Memory* - OOM).

```bash
docker run -d --name elk --network elk-red -p 5601:5601 -p 9200:9200 -p 5044:5044 -e ES_JAVA_OPTS="-Xms2g -Xmx2g" sebp/elk
```
![Contenedor ELK](img/Captura%20de%20pantalla%202026-02-20%20131206.png)

**3. Despliegue del contenedor víctima (Filebeat):**
```bash
docker run -d --name filebeat --network elk-red -p 8080:80 -p 2222:22 --memory 2g --memory-swap 2g nginx-filebeat
```
![Contenedor víctima](img/Captura%20de%20pantalla%202026-02-20%20131212.png)

**4. Entrar en la máquina víctima:**
```bash
docker exec -it filebeat bash
```
![Acceso a contenedor](img/Captura%20de%20pantalla%202026-02-20%20131219.png)

### Instalación y configuración dentro del contenedor víctima

**5. Actualizar repositorios e instalar las herramientas necesarias:**
```bash
apt update
apt install openssh-server snort nano nginx -y
```
![Instalación de herramientas](img/Captura%20de%20pantalla%202026-02-20%20131234.png)

**6. Iniciar servidor SSH:**
```bash
service ssh start
```
![Inicio SSH](img/Captura%20de%20pantalla%202026-02-20%20131240.png)

## Configuración del IDS: Snort
Duration: 0:08:00

Snort es el encargado de vigilar la red. Es un Sistema de Detección de Intrusos (IDS) clásico que revisa todo el tráfico que pasa.

* **Cazando ataques SSH:** Creamos una regla específica para pillar intentos de acceso no autorizados. Salta en cuanto detecta 10 o más intentos de conexión al puerto 22 en menos de 60 segundos (SID 3000003).
* **Vigilando los Pings (ICMP):** Para enterarnos si alguien anda trasteando o escaneando la red, metimos una regla más general. Alerta cada vez que ve pasar un paquete ICMP (`msg:"Ping ICMP Detectado"; sid:3000003; rev:1;`).

**7. Editar reglas locales de Snort:**
```bash
nano /etc/snort/rules/local.rules
```
*(Añadir las reglas correspondientes para SSH e ICMP)*
![Reglas de Snort](img/Captura%20de%20pantalla%202026-02-20%20131247.png)

**8. Iniciar Snort en segundo plano:**
```bash
snort -q -c /etc/snort/snort.conf -i eth0 -k none -l /var/log/snort -A fast -D
```
![Ejecución Snort](img/Captura%20de%20pantalla%202026-02-20%20131253.png)

## El camino de los Logs: Filebeat a Logstash
Duration: 0:07:00

* **Filebeat:** Hace de chivato. Lee las alertas de Snort (`/var/log/snort/alert`) y se las pasa al puerto 5044 de Logstash.
* **Logstash:** Es el filtro. Pilla los datos brutos, los clasifica, añade información y se lo deja mascado a Elasticsearch.

**9. Editar configuración de Filebeat:**
```bash
nano /etc/filebeat/filebeat.yml
```

*Contenido de `filebeat.yml`:*
```yaml
filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /var/log/nginx/*.log
  - type: log
    enabled: true
    paths:
      - /var/log/snort/alert

output.logstash:
  hosts: ['elk:5044']
```
![Configuración Filebeat](img/Captura%20de%20pantalla%202026-02-20%20131346.png)

**10. Iniciar Filebeat:**
```bash
service filebeat start
```
![Inicio Filebeat](img/Captura%20de%20pantalla%202026-02-20%20131354.png)

## Visualización y Validación: Pruebas de Ataque
Duration: 0:10:00

La idea de todo esto no es coleccionar logs ilegibles, sino convertirlos en información útil de un vistazo en el dashboard de Kibana: contadores de alertas críticas (ICMP, SSH), lista negra de IPs atacantes.

Lanzamos ataques simulados desde un Kali Linux corriendo en WSL para ver cómo reaccionaba.

**Test 1: Mapeo de Red**
* **La Simulación:** 4 típicos pings (ICMP) al servidor víctima (`docker exec -it filebeat ping -c 4 8.8.8.8`).
* **Lo que detectamos:** 4 alertas cantando "Escaneo ICMP" (`SID 3000003;REV,2`).
* **En Kibana:** Subida en el gráfico y el contador sumando 4.

```bash
docker exec -it filebeat ping -c 4 8.8.8.8
```
![Prueba de ping](img/Captura%20de%20pantalla%202026-02-20%20131414.png)

**Test 2: Aporreando la puerta (Fuerza Bruta SSH)**
* **La Simulación:** Tirar de Hydra con diccionarios comunes.
* **Lo que detectamos:** Lluvia de alertas críticas de SSH.
* **En Kibana:** Los contadores se dispararon.

```bash
hydra -L usuarios.txt -P claves.txt -s 2222 -o resultados.txt -t 4 ssh://127.0.0.1
```

## Tropezones, Soluciones y Conclusiones
Duration: 0:05:00

Implementar esto no fue fácil. Nos encontramos problemas, pero solucionarlos fue parte del proyecto.

* **Falta de RAM:** Limitar memoria en Docker con `--memory` y `ES_JAVA_OPTS`.
* **Filebeat no preinstalado:** Instalación manual con `apt update && apt install`.
* **Snort confuso en Docker:** Engañarlo con `-k none` para ignorar chequeos (*Checksum Offloading*).
* **Fallo de puertos:** Mapear puertos no habituales (2222 en vez de 22) en la red virtual.

### Logros y Aprendizajes
Conseguimos dejar fino un SIEM operativo con herramientas *open source*. Este laboratorio dio rodaje en cómo se mueve la info en un SIEM, gestionar redes Docker reales, y afinar un IDS para evitar el *ruido*.
