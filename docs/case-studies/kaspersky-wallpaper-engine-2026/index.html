Contexto y Vector de Ataque

El 16 de junio de 2026, Kaspersky documentó una campaña activa de distribución de malware que aprovecha Wallpaper Engine, una popular aplicación de Steam para fondos de pantalla animados. El software Wallpaper Engine NO está comprometido — el vector de infección son wallpapers maliciosos subidos por atacantes a Steam Workshop (el marketplace de contenido generado por usuarios).

Wallpaper Engine permite fondos de tipo "aplicación", que son esencialmente ejecutables de Windows disfrazados de fondos de pantalla. Los atacantes aprovechan esta funcionalidad para distribuir malware oculto en contenido aparentemente legítimo, incluyendo fondos con temática de anime y otros diseños populares.

Este tipo de ataque se enmarca dentro de los Ataques a la Cadena de Suministro (Supply Chain Attacks), donde el vector de compromiso no es el software principal, sino el contenido de terceros que se distribuye a través de él. Este patrón ha sido observado previamente en incidentes como event-stream (npm, 2018), ua-parser-js (npm, 2021) y el intento de backdoor en xz-utils (2024).

Mecanismo de Infección

Los wallpapers maliciosos emplean múltiples técnicas para ocultar y ejecutar el payload:

  • Ejecutables embebidos: Archivos .exe ocultos dentro del paquete del wallpaper
  • Archivos comprimidos con contraseña: El código malicioso está protegido; la clave puede aparecer en el nombre del fondo, en archivos de configuración, o se descifra automáticamente al abrir el wallpaper
  • Ofuscación de código: Uso de empaquetadores y ofuscadores para evadir detección
  • Nombres de archivo legítimos: Archivos con nombres que imitan componentes legítimos de Wallpaper Engine

Técnicas de Evasión

  • Ejecución retardada: El malware puede permanecer inactivo inicialmente para evitar sospechas
  • Persistencia: Creación de tareas programadas y registros de inicio
  • Aprovechamiento de confianza: Uso de Steam Workshop como fuente "oficial"

Mecanismo de Propagación

Esta campaña sigue un ciclo de vida de ataque a la cadena de suministro con amplificación: 

1. Compromiso Inicial
   ├─ Atacante crea cuenta en Steam
   ├─ Sube wallpaper malicioso a Steam Workshop
   └─ Usa técnicas de SEO y nombres atractivos

2. Distribución
   ├─ Víctima busca fondos de pantalla
   ├─ Encuentra wallpaper malicioso (apariencia legítima)
   └─ Descarga e instala el wallpaper

3. Ejecución
   ├─ Wallpaper se ejecuta como aplicación
   ├─ Payload malicioso se activa en segundo plano
   └─ Infección del sistema

4. Exfiltración
   ├─ Robo de token de sesión Steam
   ├─ Instalación de backdoor (DarkKomet)
   └─ Descarga de malware adicional (Lumma, Vidar, etc.)

5. Propagación (Amplificación)
   └─ Atacante usa cuenta de Steam robada
       └─ Sube más wallpapers maliciosos
           └─ Ciclo se repite con mayor credibilidad

Factor Clave: Credibilidad de la Cuenta

Los atacantes aprovechan que una cuenta de Steam con biblioteca grande, muchos juegos y reseñas positivas genera más confianza que una cuenta recién creada. Esto permite que el ciclo de infección se amplifique exponencialmente.

Aclaración Técnica: 2FA y Tokens de Sesión

Concepto Fundamental

El malware NO "salta" el 2FA de Steam. El factor de autenticación de dos pasos (2FA) ya se había superado cuando el usuario inició sesión y Steam generó el token de sesión.

Lo que hace el malware es robar el token de sesión existente del disco y reutilizarlo desde otro PC, que es exactamente para lo que están diseñados los tokens de sesión.

Por esto, Kaspersky no menciona el 2FA en su reporte: no es el vector relevante en este ataque.

¿Qué protege realmente el 2FA?

  • ✅ Contra que alguien adivine tu contraseña
  • ❌ NO protege contra el robo de tokens de sesión ya autenticados
  • ❌ NO protege contra acceso desde dispositivos comprometidos
  • ❌ NO protege contra keyloggers o malware en el dispositivo local

Referencia: NIST SP 800-63B §5.1 (Session Management)

Lección Aprendida

Los ataques a la cadena de suministro no son teóricos — son una amenaza real y recurrente en el ecosistema de desarrollo de software y distribución de contenido.

Recomendaciones de Mitigación

Para Usuarios

Medidas Críticas

  • Verificar la reputación del creador del wallpaper antes de instalar
  • Revisar reseñas y comentarios (buscar patrones sospechosos)
  • Preferir creadores con historial verificado y alta actividad en Steam
  • Evitar descargas de cuentas recién creadas o con poca reputación
  • Usar VirusTotal para analizar archivos descargados
  • Ejecutar Wallpaper Engine con permisos limitados (no como administrador)
  • Revisar sesiones activas de Steam periódicamente en configuración
  • Habilitar Steam Guard (2FA) — aunque no protege contra robo de tokens

Para Desarrolladores de Plataformas

Medidas de Plataforma

  • Implementar escaneo automático de archivos subidos con múltiples motores antivirus
  • Sistema de reputación para creadores de contenido (límite de subidas para cuentas nuevas)
  • Sandboxing: Ejecutar contenido de usuarios en entornos aislados
  • Transparencia: Mostrar advertencias claras sobre riesgos de contenido de usuarios
  • Verificación de cuentas de creadores populares
